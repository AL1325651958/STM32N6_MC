# STM32 MiniCraft 玩法清单与开发优先级

> 目标：在 STM32N6570-DK 上逐步构建一个可玩的第一人称体素沙盒游戏，先完成稳定、完整的单人玩法循环，再扩展生存、探索与建造内容。
>
> 本文状态以当前工程源码为依据，更新日期：2026-10-21。`已实现` 表示源码中已有相应基础逻辑，不代表已经完成板上性能、触屏和长时间运行验证。

## 1. 优先级说明

| 优先级 | 目标 | 完成定义 |
|---|---|---|
| P0 | 核心体验可靠 | 触屏、移动、交互、渲染和存档在开发板上稳定可用；玩家能持续游玩而不丢档或卡死 |
| P1 | 完成核心生存循环 | 资源采集、背包、合成、工具、加工与建造构成可持续的成长路径 |
| P2 | 增加生存与探索 | 玩家有生命、食物、昼夜、敌人、矿洞和探索奖励等目标 |
| P3 | 扩展建造与生态 | 增加农业、动物、建筑部件和世界差异，支持多种游玩方式 |
| P4 | 高成本进阶玩法 | 自动化、复杂流体、更多维度、首领与联机等系统 |

同一优先级中的序号就是建议实施顺序。优先完成依赖较少、能验证玩法循环的项目。

## 2. 当前工程基础

工程已有一套运行于 STM32N6570-DK 的第一人称体素游戏原型：800×480 LCD、160×96 软件渲染视图、256×64×256 方块世界和外部 PSRAM 世界缓冲。输入使用 GT911 多点触控，存档使用 SD 卡双槽和 CRC 校验。

| 系统 | 当前源码已有的基础 | 需要继续验证或完善 |
|---|---|---|
| 第一人称控制 | 触屏摇杆移动、拖动转向、跳跃、长按挖掘、放置、快捷栏选择 | 多点触控实机稳定性、操作灵敏度、按钮命中和低帧率体验 |
| 世界与建造 | 程序生成地形、树木、水、煤铁矿和洞穴；射线选块、目标高亮、挖掘进度、放置 | 方块掉落规则、更多地形、保存和加载的实机回归测试 |
| 生存基础 | 生存／创造切换、物品槽位、有限物品、苹果恢复生命、生命值、跌落伤害、水下氧气、床与重生点 | 完整游戏规则平衡、死亡反馈、持续运行验证 |
| 合成与工具 | 34 配方、工作台、7 类工具独立耐久、四件铁质护甲、熔炉输入/燃料/输出与加工时间 | 剑已参与近战，弓箭已加入远程战斗；护甲可穿戴并减伤、损耗；木材变体已加入；板上交互待测 |
| 背包 | 32 格背包、前 8 格快捷栏、64 堆叠、点选移动/拆分/合并/交换、箱间转移 | 板上触控与可读性待测；无拖拽动画 |
| 存档 | 双世界双槽 v6，含背包、工具、容器、熔炉、床、树苗和敌人；兼容 v1-v5 | 主机迁移通过；断电恢复待板上验证 |
| 生物与世界事件 | 最多 8 个夜间地面敌人、近战攻击和受击；v4 持久化 | 已加入单格越障、洞穴生成、箭矢掉落和露天黎明清除；无全局寻路/行走动画；板上性能待测 |

## 3. P0：稳定、可操作的基础沙盒

这是所有后续玩法的前置条件。先完成板上验证和明显影响体验的问题，再增加大量内容。

| 顺序 | 玩法／任务 | 完成标准 | 当前核对状态 |
|---|---|---|---|
| 1 | 启动与触屏校验 | 冷启动、触屏初始化、I2C 回退、无触屏提示均有确定行为；连续操作不会失去输入 | 基础已有；新版板上待复测 |
| 2 | 移动与视角 | 摇杆支持前后左右及斜向移动；斜向不加速；拖动视角平滑，松手停止移动 | 基础已有；新版板上待复测 |
| 3 | 跳跃与碰撞 | 玩家可以稳定站在方块上、跳跃和落地；不能穿墙、穿地或穿越地图边界 | 主机通过；用户旧版板上通过；新版待复测 |
| 4 | 瞄准反馈 | 准星指向可交互目标时目标清晰高亮；显示合理的交互范围和挖掘进度 | 基础已有；新版板上待复测 |
| 5 | 挖掘与放置 | 挖掘耗时有反馈；放置位置与准星目标一致；禁止放进玩家身体或不可放置区域 | 长按450ms开始；放置/满包保护主机通过 |
| 6 | 触屏多指操作 | 移动、视角和操作按钮可用不同手指同时控制；抬起或丢失触点后输入状态正确复位 | 保留多指角色；菜单/存档清理触点；板上待验 |
| 7 | 创造模式 | 无限选块、快速建造、无生存伤害；方便测试地形、碰撞、渲染和建造 | 两页完整目录，点标题翻页；全部可用物品可达主机通过，板上待复测 |
| 8 | 新建与切换世界 | 两个世界内容隔离；切换前保存当前世界；SD 不可写时给出提示，不破坏现有存档 | 基础已有；新版板上待复测 |
| 9 | 保存与继续 | 手动和自动保存后可重启继续；损坏存档不会被静默覆盖；旧存档有明确兼容行为 | 基础已有；新版板上待复测 |
| 10 | 性能基线 | 记录静止、转头、移动、挖掘、打开背包和存档时的 FPS、最长帧耗时及 RAM 使用 | 部分；旧版实测15FPS；新增MAX/保存耗时 |
| 11 | 画面和界面可读性 | LCD 上文字、准星、快捷栏、生命和通知可辨认；UI 不遮挡关键目标与主要操作区域 | 部分；九种预览已检查；LCD待实机 |
| 12 | 基础回归测试 | 核心世界逻辑和存档在主机测试通过；板上完成触控、显示、SD 卡读写流程验证 | 主机通过；新版板上待验 |

**P0 验收目标：**玩家能够探索地表、挖掘方块、放置方块、跳跃、保存世界并重启继续游戏；创造模式可用于快速测试建造。

## 4. P1：资源、背包、合成与建造循环

优先顺序的核心是先明确物品和存储规则，再扩充配方。当前源码已补齐背包格子、物品转移、箱子和定时熔炉；主机测试通过，板上验收尚待完成。

| 顺序 | 玩法／任务 | 完成标准 | 当前核对状态 |
|---|---|---|---|
| 13 | 物品类型与掉落规则 | 区分可放置方块、材料、工具和消耗品；每种方块定义破坏后获得的物品 | 已实现；采集直接入包 |
| 14 | 有限物品堆叠 | 定义每格最大数量、拾取／采集时背包已满的行为及数量上限；放置方块会消耗库存 | 已实现并通过主机测试 |
| 15 | 有槽位的背包 | 以有限格子存放物品；能选中、移动、合并和拆分；满包时采集行为明确 | 已实现；32格，点选移动/合并/拆分/交换 |
| 16 | 快捷栏与背包联动 | 快捷栏是背包槽位的映射；切换快捷栏不丢物品；数量、工具状态和选中状态同步显示 | 已实现；前8格为快捷栏 |
| 17 | 采集工具规则 | 徒手、镐、斧、铲等工具有用途和采集条件；错误工具不能获得不应掉落的材料 | 已实现；镐分级，斧铲加速 |
| 18 | 基础配方与制作反馈 | 每个配方显示材料数量、制作结果、缺少材料原因和可制作状态；制作后正确扣除材料 | 已实现；34项，材料/状态/失败回滚；小麦可合成面包 |
| 19 | 工作台 | 玩家放置并靠近工作台后可打开制作界面；离开交互范围后不能继续使用 | 已实现；交互打开，检查附近工作台 |
| 20 | 木质工具和基础升级 | 用木材制作木镐；木镐可以采集圆石；用圆石和木棍制作石镐 | 已实现并通过主机测试 |
| 21 | 工具种类与耐久 | 增加斧、铲和剑；每种工具的适用目标、速度、耐久及损坏反馈清楚 | 部分；七类工具独立耐久（含弓）；剑参与近战；护甲耐久已加入 |
| 22 | 矿物采集与分级 | 煤矿、铁矿受工具等级限制；不同矿物有明确掉落和用途；铁矿不能被低级工具错误采集 | 已实现并通过主机测试 |
| 23 | 可用的熔炉加工 | 熔炉拥有输入、燃料、输出和加工时间；煤炭或木炭作为燃料；断电重启后状态一致 | 已实现；5秒/件；煤/原木/木板燃料 |

| 25 | 箱子和储物 | 放置箱子后可以打开；物品能在背包与箱子间转移；箱子状态可保存 | 已实现；6箱，每箱24格 |
| 26 | 食物与恢复 | 苹果等食物可以使用并消耗；生命恢复上限正确；饥饿值影响生存并能被食物补充 | 主机已实现；板上待验；苹果/生肉恢复生命和饥饿，饥饿归零造成伤害 |

## 8. STM32 实现约束与设计规则

| 领域 | 建议规则 |
|---|---|
| CPU 与帧时间 | 每个玩法都要测量最坏帧耗时；地形扫描、实体更新、存档和渲染不要集中在单帧完成 |
| RAM | 方块世界当前使用约 4 MiB，另有约 4 MiB 保存缓冲；新增背包、实体、区块缓存和临时渲染缓冲前检查 PSRAM 布局与链接映射 |
| 渲染 | 先维持低分辨率世界视图和独立 UI；昂贵效果按距离、可见性或低频节奏更新 |
| 世界更新 | 避免每帧遍历约四百万个方块；使用受影响坐标、有限队列或分帧任务处理变化 |
| 实体 | 为生物、掉落物和投射物设定固定最大数量；超出上限时要有确定处理策略 |
| 存档格式 | 每次增加持久状态都要更新版本、长度和 CRC 校验；保留旧版读取或提供明确迁移策略 |
| 断电恢复 | 写入过程中不能破坏唯一有效存档；保留双槽轮换、写后回读校验并验证异常断电恢复 |
| 输入体验 | 触控操作应能组合使用；菜单打开时冻结游戏交互；关闭菜单后重置过期触点状态 |
| 玩法参数 | 移动速度、挖掘时间、生命、伤害、生成数量和配方尽量集中配置，便于板上调试 |
| 测试 | 主机测试覆盖世界逻辑、配方和存档；开发板测试覆盖触屏、LCD、缓存同步、PSRAM、SD 与长期运行 |
